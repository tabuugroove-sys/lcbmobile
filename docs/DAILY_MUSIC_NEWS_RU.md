# Ежедневный музыкальный выпуск 16:9

## Расписание и исполнение

Сервер `209.126.1.234`, Windows runtime `C:\lcbmobile-news`, задача
`LCBMobile Daily Music News`. PowerShell entrypoint: `scripts/run_server_daily.ps1`.
Python: `scripts/run_daily_music_news.py`. Первый слот **15:00 America/Sao_Paulo**;
дальше повторная проверка каждые 15 минут. Временная зона Windows не влияет на
Python gate. Внутри запуска максимум пять попыток с паузой 200 секунд.

GitHub workflow `daily-legal-multinews.yml` теперь запускает тот же динамический
bulletin как облачный резерв в 16:00, 18:00 и 21:00 BRT. Три Shorts остаются
в прежних слотах 09:13 / 14:13 / 19:13 BRT. Mac не публикует длинный выпуск:
его существующий media worker только скачивает дополнительные кадры, когда
серверная загрузка не удалась. Без доступного Mac поиск продолжается в облаке.

## Выбор и монтаж

- Пять разных музыкальных артистов, новости сегодняшнего / вчерашнего дня.
- Общие RSS + `config/daily_music_sources.yaml` (POPline, работающий Hugo Gloss).
  Billboard Brasil берётся с официальных статей: `/feed/` перенаправляет на HTML.
- Новости, уже использованные в Shorts, допускаются в ежедневный обзор.
  Повтор статьи из предыдущего длинного выпуска блокируется отдельно.
- Для каждого артиста динамический YouTube-поиск, до трёх 90-секундных источников.
  Запасной Mac-запрос изолирован ключом `horizontal-YYYY-MM-DD`, не заменяет
  30-секундные клипы основного Shorts-пайплайна.
- Минимум два разных видеоисточника на сюжет; предыдущие источники длинного
  выпуска исключаются. Нельзя лупить / повторять уже использованный интервал.
- Автоматически проверяются лица и яркость в выборках исходных видео.
  Детектор лиц **не распознаёт личность**: совпадение артиста с кадром остаётся
  ограничением автоматического поиска. Для ревью сохраняются контактные листы.
- `src/video/horizontal_news.py`: 1920x1080, голос ElevenLabs мужской pt-BR,
  скорость 0.82, настоящие timestamp-субтитры, главы с фактическим временем.
  Исходный звук видео отключён. Музыка 25%, один проход трека, без лупа.
- FFmpeg полностью декодирует итог. Чёрные сцены, паузы >2 секунд,
  повторные интервалы или недостаточная длина блокируют публикацию и отправляют
  ошибку в urgent-бот, после чего следует повторная попытка.
- YouTube-кадры записываются с честными сведениями об источнике; стандартная
  YouTube-лицензия не выдаётся за CC. Описание отмечает архивный характер кадров.

## Публикация и дедуп

Описание содержит `Radar Musical edition=YYYY-MM-DD`. Перед монтажом и загрузкой
оба исполнителя проверяют **реальный канал** `UC-TFUUc4YHleNoIFXBVaj7A` и последние
50 загрузок, включая private staging. Видео сначала загружается приватно.
После обработки публичным становится наиболее ранний видимый выпуск с этим
маркером. После сбоя обработка продолжается по тому же video ID / resumable URI.
Неизвестный исход upload нельзя исправлять слепым повторным insert.

Это сверка через YouTube, не распределённая транзакция: задержка видимости API
остаётся остаточным риском при строго одновременных запусках. Сервер и GitHub
разнесены на час; на каждом хосте запрещены параллельные экземпляры.

`publication-receipt.json` и успешный маркер БД появляются только после проверки
public-статуса и обработки. Resumable URI хранится рядом с OAuth в `.daily-upload-DATE.json`,
не в публичных артефактах. Ошибки отправляются в urgent-бот. `--preflight` не
создаёт ни голос, ни видео, ни публикацию.

## Аналитика и подстройка

`src/analytics/youtube_metrics.py` загружает реальные просмотры и
`subscribersGained` из YouTube Analytics API; это подписчики, приписанные ролику,
не изменение общего числа подписчиков канала. До исправления OAuth uploader и
comment responder при refresh сужали список scopes и отключали Analytics.
Теперь загрузка существующих credentials сохраняет все выданные разрешения.

`src/analytics/scorer.py` действительно использует исторические результаты:
источник, категория, слова заголовка, тематические группы и свежесть. Результат
ролика = `log1p(views) + 1.75 * log1p(subscribersGained)`; лайки / комментарии
не влияют. Тематический lift с малой выборкой сглаживается к среднему канала.
Новый bucket `family_reveal` учитывает семейные истории. «Критика альбома» больше
не считается публичным конфликтом только из-за слова `critica`.

Известные длинные выпуски отделены от Shorts через `youtube_metrics.content_format`.
Пока для длинного формата мало истории, отбор его сюжетов опирается на удачные
темы Shorts. Это обновляемый ранжировщик, а **не обучение весов LLM** и не
гарантированный прогноз просмотров. Lifetime-метрики не полностью уравнивают
возраст роликов; top-200 история имеет смещение в сторону уже успешных видео.

Сохраняются `candidate_scores` с причинами и выбранными fingerprint, а также
`package.json`, `timeline.json`, `chapters.json`, `qa-report.json`,
`final-review.jpg` и `publication-receipt.json` в `out/daily_music_news/DATE`.

локальные уже проверенные fixture-файлы `out/horizontal_2026-10-03`, не публикует.
